# Pre-commit Validator

## Overview
コード変更後にprekを使用して静的解析を実行し、すべてのpre-commitフックが通ることを確認します。問題がある場合は自動修正を試み、手動修正が必要な場合はガイドします。

## Workflow
1. プロジェクトにpre-commit設定（`.pre-commit-config.yaml`）があるか確認します。設定がない場合はその旨を報告して終了します。
2. `prek run --all-files`を実行してすべての静的解析ツールを実行します。
3. 出力を分析します：
   - 自動修正されたファイルを特定
   - 手動対応が必要な警告を特定
   - 解決が必要なエラーを特定
4. 自動修正が適用された場合：
   - 修正されたファイルを確認
   - `prek run --all-files`を再実行して修正を確認
   - 追加の修正がなくなるまで繰り返す
5. 手動修正が必要な問題がある場合：
   - ファイルパスと行番号を特定
   - 問題の内容を理解（フォーマット、リンティング、型チェック等）
   - 適切な修正を適用
   - よくある問題：インポートの並び順、行の長さ、末尾の空白、未使用のインポートや変数
6. 最終確認：
   - `prek run --all-files`を最終実行
   - すべてのフックが警告・エラーなしで通ることを確認
   - 最終ステータスを報告

## Examples
- ユーザー：「prekを実行して」
  - prek run --all-filesを実行し、結果を報告。問題があれば修正。
- ユーザー：「コミット前のチェックをして」
  - 静的解析を実行し、すべてのチェックが通ることを確認。

## Guardrails
- prekが設定されていないプロジェクトでは実行しません。
- 最終状態で警告・エラーがゼロになるまで完了としません。
- コードの可読性を維持しながら修正します。
- 元のコードの意図と機能を保持します。
