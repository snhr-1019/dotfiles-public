# Git Smart Commit

## Overview
Conventional Commitsを使用して、安全かつ最小限のワークフローで変更をコミットします。ステージングルール：ステージ済みの変更がある場合はステージ済みのみをコミット、なければすべての変更をステージしてコミットします。

## Workflow
1. 明示的なコミット依頼を確認し、カレントディレクトリがgitリポジトリであることを確認します。
2. `git status -sb`でステータスを確認します。
3. ステージングを判断：
   - ステージ済みの変更がある場合：ステージ済みのみをコミット対象とし、ステージされていない変更が残っていることを警告します。
   - ステージ済みの変更がない場合：`git add -A`ですべての変更をステージします。
4. 変更内容の確認：
   - `git diff --cached --stat`でステージ済みの概要を確認します。
   - 無関係な変更が含まれている場合は、コミット前に分割するか確認します。
5. Conventional Commitメッセージを作成：
   - 形式：`<type>(<scope>): <summary>`（スコープが不明な場合は省略可）
   - summaryは命令形、現在形、72文字以内。
   - 最も重要なtypeを選択。該当なしの場合は`chore`をデフォルトとします。
   - 主なtype：`feat`、`fix`、`docs`、`refactor`、`test`、`chore`、`build`、`ci`、`perf`、`style`
6. 提案したメッセージを表示し、曖昧さがある場合は確認を求めます。
7. `git commit -m "..."`でコミット（依頼がない限りamendやpushはしません）。
8. コミットしたSHAを報告し、ステージされていない変更はそのまま残します。

## Examples
- ユーザー：「コミットしてください」
  - ステージ済みの変更がない場合：すべてステージし、メッセージを提案してコミット。
- ユーザー：「git-smart-commitでコミットして」
  - このスキルを明示的に使用し、ワークフローに従います。

## Guardrails
- ユーザーが明示的にコミットを依頼していない場合は実行しません。
- ユーザーから依頼がない限り、amendやpushは行いません。
- リポジトリに変更がない場合は、その旨を伝えて終了します。
